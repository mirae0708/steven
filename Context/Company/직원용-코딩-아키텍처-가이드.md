# 💻 직원용 코딩 & 아키텍처 지식 가이드

> 출처: [[01_지식/직원용-코딩-아키텍처-가이드]] (Members → Context 승격 완료)

## 🎯 핵심 원칙

### Rule #1: 단일 진입점
- 하나의 시스템 = 하나의 메인 진입점
- `nexus_orchestrator.py` — 트레이딩, `launcher.py` — Invoice Auto, `clp_automation_v28_release.py` — CLP
- **금지**: 동일 기능 중복 진입점

### Rule #2: 오케스트레이터-모듈 분리
- Orchestrator: 흐름 제어만 (수집→분석→판단→실행)
- Core Module: 순수 비즈니스 로직
- Orchestrator가 Module 안에 로직 직접 구현 금지

### Rule #3: Template Method 패턴
```python
class BaseExpert:
    def analyze(self, data):
        self.pre_process(data)
        result = self.do_analyze()  # ← 하위 클래스 구현
        self.post_process(result)
        return result
```

### Rule #4: AI 다수결 의사결정
- 단일 AI 판단 금지 — 최소 3명 분석가 독립 분석 후 다수결
- 신뢰도 임계값(≥0.5) + 과반수(2/3) 동시 만족 시 실행

### Rule #5: Circuit Breaker 패턴
- 모든 자동화 시스템에 3단계 이상 보호 회로 필수
- 정상 → 주의 → 방어 → 비상 4단계
- 매크로/기술적/포트폴리오 리스크 3개 축 검증

### Rule #6: 설정 레이어 분리
- `.env`: API 키/패스워드 (Git 추적 금지)
- `config.json`: 환경별 설정
- `settings.py`: 코드 기본값 + 환경변수 오버라이드
- **절대**: 코드에 하드코딩 금지

## 🏗️ 아키텍처 패턴 모음

### 패턴 1: 3단계 파이프라인
```
[Parse] → [Map] → [Execute]
PDF/AI   고객코드   ERP 입력
데이터   매핑      Double OK
추출     (12회 재시도) 저장
```

### 패턴 2: Watcher 감시→자동처리
```
Watch 디렉토리 → 파일 감지 → 처리 실행 → 완료 후 재감시 (무한루프)
  - 싱글 인스턴스 (.lock 파일)
  - 예외 발생 시 로그 기록 후 재시작
```

### 패턴 3: 단일 스크립트 배포 (CLP Auto)
- 466줄 단일 파일: `load_config()` → `parse_xxx()` → `run_automation()`

### 패턴 4: JS 주입 프론트-백 연결
- Python(Selenium)에서 JavaScript 실행으로 레거시 웹 자동화

### 패턴 5: Async Auto-Retry
```python
def ensure_customer(data, attempt=0):
    try:
        return create_or_find(data)
    except DuplicateError:
        if attempt >= 12: raise MaxRetryError
        return ensure_customer(data, attempt + 1)
```

## 🐍 코딩 규칙

### 네이밍 컨벤션
| 항목 | 규칙 | 예시 |
|------|------|------|
| 클래스 | PascalCase | `NexusOrchestrator` |
| 함수/변수 | snake_case | `process_invoice()` |
| 상수 | UPPER_SNAKE | `MAX_RETRY = 12` |
| 비공개 | _prefix | `_snapshot_files()` |
| 모듈 | snake_case | `risk_manager.py` |
| 디렉토리 | kebab-case | `02-Knowledge/` |

### 필수 규칙
- 타입 힌트 의무화 (`def f(x: str) -> Optional[Dict]:`)
- 로깅: `logger.info("msg: %s", var)` — f-string 금지
- 에러: 구체적 예외 + 지수 백오프 재시도
- 함수: 단일 책임 원칙, 200줄 초과 금지
- import: 표준 → 서드파티 → 로컬 (빈 줄 구분)

## 🧪 테스트 전략
| 계층 | 대상 | 도구 | 빈도 |
|------|------|------|------|
| Unit | 개별 함수 | pytest | 매 PR |
| Integration | 모듈 간 | pytest+mock | 매 릴리즈 |
| E2E | 전체 파이프라인 | pytest+Selenium | 주간 |

## 🔒 보안 수칙
1. API 키 절대 Git 커밋 금지 → `.env`
2. config.json 비밀번호 평문 금지 → 환경변수 참조 `${VAR}`
3. Selenium 로그인 정보 하드코딩 금지
4. 임시파일 정리 필수 → `try/finally` or `contextlib`

## 📋 안티패턴 금지
| 안티패턴 | 이유 |
|:---------|:-----|
| 하드코딩 | 유출 위험, 변경 어려움 |
| 매직 넘버 | 의도 불명 |
| 200줄+ 함수 | 읽기/테스트 불가 |
| 무성 catch `except: pass` | 버그 은폐 |
| 중복 진입점 | 혼란 |
| f-string 로깅 | lazy evaluation 손실 |
| 전역 mutable | 스레드 안전 위반 |
