# 🔄 Hermes Swap 재축적 패턴 진단 (5/25)

> 마지막 업데이트: 2026-05-25

## 개요

Hermes Gateway (port 8642)에서 발생하는 **Swap 재축적 현상** — WSL 재부팅 직후 0B 수준이었다가 수일~수주에 걸쳐 Swap 사용량이 점진적으로 증가하는 패턴.

## 타임라인

| 날짜 (KST) | Swap 사용량 | Delta | 구분 |
|:-----------|:----------:|:-----:|:-----|
| 5/24 00:45 | **780KiB** | — | ✅ **재부팅 효과 (사실상 0B)** |
| 5/25 02:01 | **780KiB** | 0% | ✅ 유지 |
| 5/25 08:33 | **35MiB** | **~45x 증가** | ⚠️ 재축적 조짐 |
| 5/25 11:00 | **436MiB** | **~12.5x/3h** | 🚨 심각 — 300MiB 임계 초과 |
| 5/25 12:46 | **434MiB** | 소폭 안정화 | 🚨 심각 지속 — 재부팅 권장 |
| 5/18~5/22 | **602MiB** (peak) | — | ❌ 재부팅 필요 (7일 누적) |

## 관찰된 패턴

1. **초기 (재부팅 후 ~24h)** — Swap 사용량 0~1MiB (정상)
2. **중기 (2~5일)** — 35~100MiB 서서히 증가
3. **말기 (7~14일)** — 300~602MiB까지 축적 → Gateway 응답 지연
4. **해소** — WSL 재부팅으로만 완전 해소. Gateway 단독 재시작으로는 Swap 반환되지 않음.

## 🚨 5/25 특이사항: 급가속 재축적 패턴

5/25 일일 추세에서 **이전 주기 대비 재축적 속도가 50배 이상 가속**됨:
- 이전 주기: 2~5일 → 35~100MiB (하루 평균 ~15MiB)
- 5/25: **08:33→11:00, 2.5h 만에 35→436MiB (+401MiB, 시간당 160MiB)**
- 이후 11:00→12:46: 436→434MiB로 소폭 안정화

**의심 원인 업데이트:**
- **Gateway 4일차 메모리 누수 가속** — Gateway 프로세스 RSS 728MiB (5/24 17:40 재부팅 후 4일차)로 30일차 31일차 Chronic 누적 효과
- **MetaClaw skills_only 모드의 잔여 누수** — 5/23 이후 skills_only 모드로 완화했으나 완전 해소되지 않음, 4일차에 임계치 도달
- **UVX Python 런타임 캐시 4일 누적** — 시간 경과에 따라 비례 증가

**가설**: 4일차에 특정 임계치(MetaClaw 메모리 풀 한도? Python GC 트리거?)를 넘으면 Swap 축적 속도가 급격히 증가. 4일차 도달 전(3일 이내) 재부팅 사이클이 최적.

## 의심 원인

- **MetaClaw 메모리 누수** — 5/23 이전 major leak 확인됨. skills_only 모드로 완화했으나 잔여 누수 가능성.
- **Python MCP 서버** — Zombie 상태 서버 6개(obsidian, googledrive, anythingllm 등)가 Swap에 남아있을 가능성.
- **UVX 캐시** — `uvx` 기반 MCP 서버들의 Python 런타임 캐시 WSL 메모리 상주.
