# 05. 컨텍스트와 메모리

> **Long Context, Memory Systems, RAG, Context Window**  
> 관련 논문: ~15편 (10_Wiki/Artificial_Intelligence/LLM)

## 1. Long Context 문제

### 현재 상황
- GPT-4: 128K 토큰
- Gemini: 1M 토큰 (Pro), 10M 토큰 (Ultra)
- Claude: 200K 토큰
- Qwen: 128K-1M 토큰

### 한계
- **O(n²) attention 비용** — 컨텍스트 길이에 따라 2차 증가
- **Lost-in-the-Middle** — 중간 정보 손실
- **KV Cache 메모리 폭발**
- **사실상의 효과적 컨텍스트**는 명시된 최대치보다 훨씬 낮음

## 2. Long Context 최적화

### 🔹 Context Memorization (2026.05)
- **Efficient Long Context Generation**
- **핵심:** 긴 컨텍스트에서 중요한 부분만 메모리에 저장
- **방법:**
  - 중요도 기반 선택적 저장
  - 덜 중요한 컨텍스트는 압축
- **결과:** 128K 컨텍스트에서 메모리 60% 절감

### 🔹 Context, Reasoning, and Hierarchy (2026.05)
- **비용-성능 연구:** 긴 컨텍스트의 실제 효용
- **주요 발견:**
  - 많은 작업에서 32K면 충분
  - 128K 이상은 추론 품질 저하
  - 계층적 처리(Hierarchical)가 효과적

### 🔹 Unlocking the Working Memory (2026.05)
- **Large Language Models의 Working Memory 확장**
- LLM의 작업 기억(working memory)을 인간처럼 제한적이지만 효율적으로 관리
- **방법:** 최근 토큰에 가중치 부여, 오래된 정보는 압축

## 3. Memory Systems

### 🔹 Rethinking Memory (2026.05)
- 메모리를 **연속적으로 진화하는 연결성**으로 재정의
- 기존: 정적 저장소 (Database)
- 제안: 동적 관계 네트워크 (Continually Evolving Connectivity)
- **시사점:**
  - Hermes의 Layer Memory System과 일치
  - L0-L4 계층 구조의 이론적 기반

### 🔹 FORGE (2026.05)
- **Self-Evolving Agent Memory With No Weight Updates**
- **핵심:** 가중치 업데이트 없이 에이전트 메모리 진화
- **방법:**
  - 경험 -> 메모리 -> 행동 -> 경험 순환
  - 가중치 변경 없이 메모리만 업데이트
- **적용:** Hermes의 Memory System과 직접 연계 가능

### 🔹 Phasor Memory Networks (2026.05)
- **Stable Backpropagation Through Time**
- 주기 함수(phasor)로 메모리 표현
- 긴 시퀀스에서도 gradient 소실 없이 학습 가능

## 4. RAG (Retrieval-Augmented Generation)

### 기본 흐름
```
Query → Retriever → [Document1, Document2, ...]
       → Context + Query → LLM → Response
```

### 최신 발전

| 기술 | 설명 | 장점 | 단점 |
|------|------|------|------|
| Naive RAG | 단순 검색 + 생성 | 간단 | 저품질 검색 시 성능 저하 |
| Advanced RAG | Pre/Post-retrieval 최적화 | 품질 향상 | 복잡도 증가 |
| Modular RAG | 검색 모듈 교체 가능 | 유연성 | 설계 복잡 |

### RAG vs Long Context

| 항목 | RAG | Long Context |
|------|-----|:-----------:|
| 비용 | 낮음 (선별적 검색) | 높음 (전체 처리) |
| 정확도 | 검색 품질에 의존 | 모든 정보 접근 |
| 지연 시간 | 낮음 | 높음 |
| 확장성 | 무제한 (검색만 확장) | 제한적 (컨텍스트 한계) |

**💡 최신 결론:** RAG + Long Context 하이브리드가 가장 효과적

## 5. Constraint Decay (2026.05) ⚠️

- **중요 발견:** LLM 에이전트는 시간이 지남에 따라 제약 조건을 잊어버림
- **현상:**
  - 긴 대화에서 초기 지시사항 무시
  - 중간에 설정한 규칙을 나중에 위반
- **원인:** 
  - Attention dilution (긴 컨텍스트에서 주의 분산)
  - No explicit constraint tracking
- **해결:**
  - 명시적 제약 메모리 (Constraint Store)
  - 주기적 제약 리마인더
  - 메타-인지 모니터링
